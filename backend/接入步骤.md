# 交通枢纽巡检系统：启用云端账号后台

GitHub 前端仓库：ayciahsong-crypto/my-web。
Supabase 项目：byvywuwfxxioyllssgwi。

## 1. 初始化数据库

进入 Supabase 项目左侧 SQL Editor（`>_` 图标），新建查询。
将 `01-init.sql` 全文复制到编辑器，点击 Run。
成功后会创建四张 inspection_ 开头的表、私有照片桶、账号触发器及行级权限。
脚本可重复执行，不删除已有打卡；默认点位只在点位表为空时创建。

## 2. 创建首个主管

进入 Authentication → Users → Add user → Create new user。
使用自己的邮箱，设置独立密码，启用 Auto Confirm User（如有该选项）。
请自行保管密码，不要发到聊天或提交 GitHub。
打开 `02-set-first-manager.sql`，把 `请替换为主管邮箱` 换为这个邮箱，在 SQL Editor 执行。
只有项目所有者通过 SQL 才能提升主管账号；员工不能自行成为主管。

## 3. 创建员工

在 Authentication → Users 中同样创建员工账号（一个员工一个邮箱）。
在应用首页选择管理入口，用主管邮箱和密码登录。
进入“人员与权限”，刷新列表，为员工填写姓名、选择“保安”或“工程部”，保持启用并保存。
未分配角色的账号不能上传巡检照片。
当前版本不在应用里直接创建或重置密码；这些操作使用 Supabase 控制台。
建议在 Authentication 的登录 / 用户注册设置中关闭开放注册，避免无关账号注册。

## 4. 分配点位与验证

主管在“巡检配置”中设置每班轮次，新增点位并指定适用岗位。
员工用手机选择员工入口并登录，选择班次、轮次、点位，拍照后点击“上传并继续”。
必须看到“后台已接收”才算提交成功。
主管用另一个浏览器或电脑登录，刷新“账号打卡汇总”，按日期与账号筛选。
点“打卡明细与照片”可以查看每个账号的照片、设备拍摄时间和服务器接收时间，下载 JPG。

## 权限规则

- 未登录：不能读取账号、点位、记录或私有照片。
- 待分配 / 停用：不能读取巡检数据或上传照片。
- 保安 / 工程部：读取本岗位启用点位，只能提交并查看自己的记录及照片。
- 项目主管：查看全部账号和记录，管理普通员工姓名、角色、停启用及点位和轮次。
- 普通员工不能修改配置、角色、已提交记录或照片；主管页面不能提升其他主管。
- 账号身份、点位名称、岗位、工作日期和接收时间由数据库盖章，不信任浏览器填写。
- 照片桶非公开，读取照片使用短时签名链接。拿到链接的人在有效期内可以查看，请勿分享。

## 数据与限制

- 当前是一套 Supabase 项目对应一个巡检项目，不提供多项目隔离。
- 统计基于北京时间；晚班凌晨 00:00—06:00 的记录归到前一工作日。
- 每次提交计一次打卡；同一轮次重复拍摄分别记录。已提交轮次不等于全部点位完成。
- 设备拍摄时间仅供参考，不是照片真实性证明；尚未接入定位 / 防伪 / 考勤规则。
- 上传失败时保留当前页面重新提交；暂不支持关页后的离线队列。
- 登录保存在当前标签页的 sessionStorage，关闭后可能需要重新登录。
- 旧版 IndexedDB 本机照片不自动导入，也不会被此版本删除。应先用旧版导出备份。
- GitHub Pages 只托管代码；账号、照片和打卡保存于 Supabase，不会提交到公开仓库。
- 前端只使用 Publishable key；不要在网页、GitHub 或聊天里放 secret/service_role 密钥。

## 必做验证

1. 创建一个主管、一个保安、一个工程部测试账号。
2. 保安上传照片，主管在另一设备查询确认可见。
3. 保安尝试管理入口，应被拒绝；工程部同样不能改点位。
4. 停用保安后，再次提交应被后台拒绝。
5. 未登录用户不能访问私有照片；不应把照片桶改为 Public。

代码和脚本静态检查不能代替实际数据库和手机测试。数据库初始化前，云端功能尚不可用。
